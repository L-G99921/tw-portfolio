The **PowerBox API** connects a utility's back-office systems to EnergyGrid. A utility needs two flows working before its customers can use EnergyGrid hardware or the app:

- **Customer sync:** send customer accounts, service addresses (premises), and meter configuration from the utility's customer information system (CIS) to EnergyGrid.
- **Hardware binding:** link a DataBridge Hub or SmartLink Plug to the customer's AMI meter over the utility's wireless mesh radio (home area network).

## Audience

Backend engineers at a utility who connect their CIS and AMI head-end systems to EnergyGrid. This isn't a public consumer API.

## Authentication

Every endpoint needs an OAuth 2.0 bearer token from the utility's identity provider. EnergyGrid doesn't issue tokens. They usually last one hour, and you refresh them through the utility IDP. Send the token in the `Authorization` header as `Bearer <token>`. For the full exchange, see [Configure authentication](/docs/integration-guide#step-2-configure-authentication-oauth) in the integration guide.

## Base URL

```
https://api.energygrid.example/v1
```

A staging environment is available for integration testing. Pick it in the **Servers** list on any operation page.

## Conventions

- **Content type.** `application/json` for requests and responses.
- **Identifiers.** `clientId`, `externalSiteId`, and `meterId` are strings owned by the utility CIS. EnergyGrid never generates them.
- **Account status.** `AcctStatus` uses the utility's own codes, such as `A` for active and `F` for final. EnergyGrid stores the value as received. For the full list, see [account status codes](/docs/integration-guide#account-status-codes).
- **Idempotency.** Customer sync is idempotent on `clientId`, so repeating it is safe. Binding isn't: a second bind for the same meter returns `400` with `METER_ALREADY_BOUND`.
- **Errors.** Errors use the HTTP status code. Login and bind errors also return an `errorCode` in the body. See [error codes](/docs/integration-guide#error-codes).

## Versioning

The version is in the path (`/v1`). Breaking changes ship as a new major version, and the old one stays available for at least 90 days. New optional fields and new values on extensible enums ship in the current version.

## Try it in the browser

Every operation page has a **Send API Request** panel. The hosts in this spec don't exist, so the site answers those requests in your browser with a simulated server built from this spec. Use any value as the bearer token.

## About this sample

EnergyGrid is a fictional platform, documented end to end on this site. The contracts and conventions reflect a realistic utility integration API. The hostnames don't resolve.
